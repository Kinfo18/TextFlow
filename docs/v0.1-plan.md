# V0.1 — Plan: expansión de texto lista para uso diario

- Fecha: 2026-10-02 · Base: [`fase0-informe.md`](fase0-informe.md), spec V2 §4 y §31, ADR-0001–0007
- **Objetivo:** que el usuario sustituya aText en su jornada de trabajo con TextFlow.
- **Principio de orden:** primero lo que permite usarlo a diario (H1), después persistencia y edición, y al final el pulido.

## Criterios de "listo" (spec §31, adaptados)

1. Importa el backup de aText del usuario sin pérdidas relevantes: 34 menús y 293 comandos.
2. Aguanta una **jornada completa** (≥ 8 h) sin perder el hook, sin reinicios y sin errores de destino.
3. **Wrong Target Rate = 0**: nunca inserta en un destino que no superó la validación.
4. Permite **deshacer** la última inserción.
5. Funciona en Notepad, Word, Outlook, Firefox, Chrome y VS Code (matriz de Fase 0).
6. Funciona sin red, sin persistir texto escrito y sin contenido en los logs.
7. RAM en reposo < 150 MB; arranque < 2 s hasta "motor activo".

## Forma de trabajo

- TDD en Core (máquina de estados, repositorios, validador, importador); tests de escritorio solo con aviso previo, porque roban el foco.
- Cada hito termina con: build Release sin warnings, tests en verde, prueba manual del usuario, commit y push.
- Las decisiones que rompan algo de la spec §33 o de un ADR requieren un ADR nuevo.
