# V0.2 — Plan: dictado local y comandos por voz

- Fecha: 2026-10-08 · Base: spec V2 §4 (V0.2), §8 (política de dictado), §12–13, [ADR-0003](adr/0003-hotkey-dictado.md), [ADR-0005](adr/0005-candidatos-asr.md), [ADR-0007](adr/0007-motor-asr.md)
- **Requisito previo:** v0.1.0 publicada (H6 de [`v0.1-plan.md`](v0.1-plan.md)).
- **Objetivo:** mantener una tecla, hablar y que el texto aparezca en el campo donde estabas, sin internet. Cuando el dictado esté pulido, **comandos por voz**: decir «envía saludo» ejecuta el snippet `cc` igual que si lo hubieras tecleado.
- **Principio de orden:** primero dictado básico de punta a punta (H2), después la experiencia (ORB, calidad) y al final los comandos, que dependen de un reconocimiento fiable.

## Criterios de "listo"

1. **Precisión:** WER ≤ 3 % en el corpus ampliado (R10: ≥ 50 frases, con ruido de oficina y vocabulario del trabajo).
2. **Latencia:** texto insertado < 2 s (p50) después de soltar la tecla, con el modelo caliente; aviso visual < 100 ms al pulsar.
3. **Wrong Target Rate = 0:** el dictado solo se inserta en el campo capturado al pulsar; si ya no es válido, se ofrece, nunca se escribe en otro sitio (spec §8).
4. **Privacidad:** el audio nunca se guarda en disco; ni el audio ni el texto dictado llegan a los logs (test automatizado, como en v0.1).
5. **Robustez:** si el proceso de voz se cae, se reinicia solo y TextFlow (expansiones incluidas) sigue funcionando.
6. **Memoria:** la VRAM del modelo (~950 MiB) se libera tras un tiempo sin dictar (configurable).
7. **Comandos por voz:** ≥ 95 % de aciertos con las frases configuradas y **0 ejecuciones falsas** en una sesión de prueba de dictado normal.
8. Funciona sin GPU NVIDIA (respaldo en CPU), aunque más lento.

### H6 — Comandos por voz (≈4–5 días, cuando H2–H5 estén estables)

Ejemplo: dices **«envía saludo»** y TextFlow ejecuta el snippet `cc` en el campo donde estás, exactamente como si hubieras escrito `cc` (campos, `{{clipboard}}` y auto-Enter incluidos).

| # | Tarea | Hecho cuando |
|---|---|---|
| H6.1 | **Decisión de activación** (ADR): cómo distingue TextFlow un comando de un dictado normal. Candidatos: (a) atajo propio para comandos; (b) palabra inicial («comando, envía saludo»); (c) mismo atajo y frase exacta. Recomendado de partida: **(a) atajo propio**, sin riesgo de ejecutar algo mientras dictas | ADR aceptado tras probarlo el usuario |
| H6.2 | **Frases de voz por snippet** en el editor (una o varias: «envía saludo», «saludo»); se guardan en SQLite/JSON como las abreviaturas; validador de duplicados y frases demasiado parecidas | Migración + tests de repositorio e import/export |
| H6.3 | Reconocimiento: las frases configuradas se pasan al modelo como vocabulario; coincidencia tolerante (sin tildes, mayúsculas ni puntuación; distancia de edición acotada) en Core con tests | Tests: «Envía saludo.», «envia saludo», «envía el saludo» → `cc`; «envía salud» → nada si es ambiguo |
| H6.4 | Ejecución por la misma vía del motor (`ExpandContentAsync`): destino bloqueado, campos, auto-Enter, sonido | «envía saludo» en WhatsApp Web inserta y envía el texto de `cc` |
| H6.5 | **Seguridad:** nunca adivinar. Sin coincidencia clara → el ORB muestra «No reconocí el comando» (y las 2–3 frases más cercanas para elegir con el ratón o 1/2/3); nunca inserta el texto dictado como si fuera un comando | 0 ejecuciones falsas en 100 frases de dictado normal |
| H6.6 | Lista de comandos de voz en Configuración (frase → snippet), con botón «probar» | Se puede revisar y probar todo sin abrir cada snippet |

*Más adelante (V0.4, automatización segura):* comandos que no insertan texto sino que actúan: «abre Jira», «abre la carpeta de reportes». Reutilizarán las frases de H6 con el sistema de permisos de la spec §18.

## Fuera de V0.2

Modo Profesional y LLM local (V0.3; no cabe con el ASR en 4 GB de VRAM, ADR-0005), acciones de sistema por voz (V0.4), dictado continuo sin tecla, varios idiomas a la vez más allá de español con términos en inglés, guardar grabaciones.

## Riesgos

| Riesgo | Nivel | Mitigación |
|---|---|---|
| El PC de trabajo no tiene GPU NVIDIA | Alto | H0.1 primero; respaldo Parakeet CPU (≈0,6 s, WER 6 %) desde H4.2 |
| Whisper inventa texto con silencio o ruido | Alto | VAD (H4.1), descartar resultados vacíos o repetitivos |
| Comando ejecutado por error | Alto | Atajo propio para comandos (H6.1), coincidencia estricta, nunca adivinar (H6.5) |
| Contención de GPU (una ronda dio 1,7 s en S5) | Medio | Medir p95 en H0.2; aviso en Diagnóstico |
| Descarga del modelo cortada (red de este PC) | Medio | Descarga reanudable con hash (H1.4) |
| Política del PC de trabajo bloquea el micrófono a apps de escritorio | Medio | Detectar y explicar cómo activarlo (Configuración de Windows → Privacidad → Micrófono) |

## Forma de trabajo

La misma que en v0.1: TDD en Core (sesión de dictado, coincidencia de comandos, normalización), tests de escritorio solo con aviso, y cada hito termina con build Release sin warnings, tests en verde, prueba del usuario, commit, push y —desde ahora— una beta publicada (`v0.2.0-beta.N`) que llega sola a las copias instaladas.
